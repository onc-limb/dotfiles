# レビューの範囲の関門

レビューと裁定は、このタスクの範囲の中の問題だけを今回の修正対象にする。範囲の外の問題は直さずに、後続の課題として残す。

## 原則

| 原則 | 基準 |
|------|------|
| 範囲はタスクと計画で決まる | 今回の範囲は、指示書（タスク）の受け入れ条件と、計画レポートが変更するとしたファイル・振る舞い。レビューの観点の広さで範囲を広げない |
| 今回の変更が原因の問題は範囲内 | 今回の差分が入れた欠陥、今回の差分が壊した既存の振る舞い、受け入れ条件を満たさない状態は、範囲内として直す |
| 前からある問題は範囲外 | 差分の前から同じ状態だった問題、今回変更していない箇所の改善、一般的な設計の好みは範囲外とする。今回の変更で悪化したか、受け入れ条件に関わるときだけ範囲内にする |
| 範囲外は捨てずに残す | 範囲外とした指摘は、裁定の「今回の範囲外」として、場所・内容・根拠を残す。後続の課題にできる粒度で書く |

## 判定基準

| 基準 | 判定 |
|------|------|
| 前からある問題を、今回の修正対象にしている | REJECT |
| 範囲外とした指摘を、記録せずに消している | REJECT |
| 今回の差分が入れた欠陥を、範囲外として見送っている | REJECT |
