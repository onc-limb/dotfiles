計画レポート（plan.md）を、指示書（タスク）と照らし合わせて確かめてください。作り直した計画のときは、前回の見直しの結果（plan-review.md）の指摘が解消されたかも確かめてください。

次の 5 項目を、それぞれ「満たす / 計画を直せば満たす / 指示書が足りない」で判定し、根拠（計画・指示書の該当箇所、確かめたコード）を書いてください。

1. **ゴールが受け入れ条件で閉じている**: 何ができたら完了かが、外から確かめられる条件で書かれている。条件が指示書のゴールから直接導けて、指示書に無い要求を足していない。
2. **範囲外の扱いが決まっている**: やらないことが書かれている。作業中に範囲外の問題に気づいたら、直さずに報告して後続の課題に回すことが計画から読み取れる。
3. **受け入れをこの run の中で確かめられる**: 受け入れ条件ごとに、プロジェクトの中で実行できるテストかコマンドがある。人や外部の環境でしか確かめられない条件は、その旨と確かめ方が書かれている。
4. **設計判断を勝手に決めていない**: 指示書・ADR・既存のコードの約束事に無い設計判断（新しい境界・データの形・公開する振る舞いの選択など）を、計画が自分で決めていない。決める必要がある判断が残っているなら、それを挙げる。
5. **1 回の run に収まる大きさ**: 計画の作業が、1 回の実装とレビューで終えられる大きさにまとまっている。分けるべきなら、どこで分けるかを挙げる。

結果は次のどれか 1 つにしてください。

- **進める**: 5 項目をすべて満たす。
- **計画を直す**: 「計画を直せば満たす」が 1 つ以上あり、「指示書が足りない」は無い。直すべき点を、計画の作り直しでそのまま使える形で書く。
- **人に戻す**: 「指示書が足りない」が 1 つ以上ある（指示書のゴール・受け入れ条件が曖昧、指示書に無い設計判断が要る、1 回の run には大きすぎる）。人が指示書をどう直せばよいかを書く。

作り直した計画を確かめるときは「計画を直す」を選べません。満たさない項目が残るなら「人に戻す」にしてください。
